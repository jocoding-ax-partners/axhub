# Feature Specification: npx 원커맨드 온보딩

**Feature Directory**: `specs/001-npx-one-command-onboarding`
**Created**: 2026-07-10
**Status**: Draft
**Input**: axhub 온보딩이 어려워요. 터미널 명령 한 줄(`npx axhub@latest setup`)로 axhub 플러그인을 쓸 준비가 끝나게 해요. 브레인스토밍 승인 설계: `docs/superpowers/specs/2026-07-10-npx-one-command-onboarding-design.md`

## User Scenarios & Testing *(mandatory)*

### Primary User Story

axhub 를 처음 쓰는 바이브코더가 안내 페이지에서 명령 한 줄을 복사해 터미널에 붙여넣으면, 비대화형 셋업 전부(axhub CLI 설치 → 마켓플레이스 등록 → 플러그인 설치 → MCP 등록)가 자동으로 끝나요. 마지막에 "Claude Code 를 열고(이미 켜져 있으면 재시작) '처음인데 셋업해줘'라고 말하세요" 핸드오프 카드가 보이고, Claude 안에서는 대화형 단계(로그인 → GitHub App → MCP OAuth)만 남아요.

### Acceptance Scenarios

1. **Given** Claude Code 와 Node.js 가 설치된 새 머신, **When** `npx axhub@latest setup` 을 실행하면, **Then** CLI 설치·마켓플레이스 등록·플러그인 설치·MCP 등록이 모두 완료되고 핸드오프 카드가 출력돼요.
2. **Given** 일부 단계가 이미 완료된 머신(예: CLI 만 설치됨), **When** 같은 명령을 실행하면, **Then** 완료된 단계는 확인 표시와 함께 건너뛰고 나머지 단계만 수행돼요(멱등).
3. **Given** 중간 단계에서 실패한 머신(예: 네트워크 순단), **When** 같은 명령을 다시 실행하면, **Then** 처음부터가 아니라 실패 지점부터 이어져 완료돼요(재개 모델).
4. **Given** Claude Code 가 설치되지 않은 머신, **When** 명령을 실행하면, **Then** Claude Code 의존 단계는 실행하지 않고 설치 안내를 출력한 뒤 명확히 종료돼요.
5. **Given** setup 이 완료된 머신, **When** Claude Code 를 열고 "처음인데 셋업해줘"라고 말하면, **Then** 기존 대화형 온보딩이 CLI·플러그인·MCP 단계를 재수행하지 않고 로그인부터 시작해요.
6. **Given** admin 권한이 없는 사내 Windows PC, **When** 명령을 실행하면, **Then** 모든 산출물이 사용자 영역(user-scope)에만 설치되어 권한 요청 없이 완료돼요.
7. **Given** 프롬프트에 응답할 수 없는 환경(CI 파이프라인, AI 코딩 도구가 대신 실행), **When** 명령을 실행하면, **Then** 입력 대기로 멈추지 않고 안전 기본값으로 완주하거나 명확한 안내와 함께 종료돼요.
8. **Given** setup 이 끝난 머신, **When** 사용자가 설치 상태 진단을 요청하면, **Then** 네 가지 산출물(CLI·마켓플레이스·플러그인·MCP)의 상태를 각각 확인해 문제와 해결 방법을 알려줘요.

### Edge Cases

- **Node.js 미설치**: 명령 자체가 실행되지 않아요 — 안내 페이지가 Node 18+ 전제를 명시하고 설치 fallback 안내를 제공해요(이 기능 밖 경로지만 문서 요구사항).
- **네트워크 차단·프록시**: 어느 단계에서 왜 실패했는지와 다음 행동을 한국어로 안내해요. 조용한 실패나 원문 스택트레이스 노출은 실패로 간주해요.
- **Claude Code 세션을 켜둔 채 실행**: 플러그인은 재시작 후 로드되므로 핸드오프 카드가 재시작 안내를 항상 포함해요.
- **구버전 axhub CLI 가 이미 설치됨**: 최신으로 갱신해요(기존 auto-update 경로와 동일한 결과 상태).
- **애매한 실행 환경 버전(예: 지원 목록 밖이지만 동작 가능한 Node)**: 진짜 최소 요건 미만만 중단하고, 그 외에는 감지된 버전과 요구 범위를 명시한 경고 후 계속 진행해요.
- **Claude Desktop 만 있고 claude CLI 가 없음**: 기존 온보딩의 커스텀 커넥터 안내 경로로 연결해요.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 단일 터미널 명령이 비대화형 셋업 전부 — axhub CLI 영구 설치, 마켓플레이스 등록, 플러그인 설치, MCP 등록 — 를 순서대로 수행해요.
- **FR-002**: 명령이 성공적으로 끝나면 다음 행동을 알리는 핸드오프 카드를 출력해요 — Claude Code 를 열거나(켜져 있으면 재시작) "처음인데 셋업해줘"라고 말하기.
- **FR-003**: 명령은 멱등이에요 — 재실행 시 완료된 단계는 확인 표시 후 건너뛰고, 부분 실패 후 재실행하면 실패 지점부터 재개돼요.
- **FR-004**: Claude Code(claude CLI)가 없으면 Claude Code 의존 단계를 실행하지 않고 설치 안내 후 종료해요. 이때까지 수행된 단계(CLI 설치)는 유해하지 않게 남아요.
- **FR-005**: 모든 산출물은 사용자 영역(user-scope)에만 설치돼요 — admin/시스템 권한을 요구하지 않아요.
- **FR-006**: 명령은 인증을 건드리지 않아요 — 로그인·토큰·GitHub App 은 Claude 안 대화형 온보딩이 담당해요.
- **FR-007**: 설치되는 것 전체 목록, 설치하지 않는 것, 제거 방법을 사용자 문서에 공개해요(투명성 정책 정합).
- **FR-008**: 기존 대화형 온보딩은 setup 이 완료한 상태를 자동 인식하고 남은 대화형 단계(로그인)부터 이어가요 — 중복 재작업이 없어요.
- **FR-009**: MCP 가 첫 세션 전에 등록된 신규 사용자에게는 세션 중 MCP 등록에 따른 재시작 안내 절차가 나타나지 않아요.
- **FR-010**: 기존 설치 채널(문서의 수동 플러그인 설치 절차, 기존 CLI installer)과 결과 상태가 동일해요 — 어느 채널로 설치해도 같은 위치·같은 상태로 수렴하고 서로 충돌하지 않아요.
- **FR-011**: 각 단계 실패 시 원인과 다음 행동을 한국어 한두 문장으로 안내해요 — 원문 스택트레이스·내부 식별자를 사용자에게 노출하지 않아요.
- **FR-012**: 프롬프트에 응답할 수 없는 환경(터미널 입력 불가, CI, AI 코딩 도구의 대행 실행)을 감지하거나 비대화형 옵션이 주어지면, 어떤 입력도 기다리지 않고 안전 기본값으로 완주하거나 명확히 종료해요 — 입력 대기로 멈춘 채 남는(hang) 실행은 결함으로 간주해요. 비대화형 모드에서는 브라우저 열기 같은 대화형 부수 동작도 하지 않아요.
- **FR-013**: 실제 변경을 시작하기 전에 이번 실행이 설치·등록·수정할 항목과 이미 완료돼 건너뛸 항목을 출력해요 — 사용자 문서에 공개한 설치 산출물 목록과 일치해야 해요. 변경 없이 목록만 확인하는 실행 방식도 제공해요.
- **FR-014**: setup 이 만든 상태를 사후 검증하는 진단 수단을 제공해요 — 네 가지 산출물 각각의 정상 여부를 확인하고, 문제 발견 시 해결 방법 또는 다음 행동을 안내해요.
- **FR-015**: 실행 환경 점검은 두 등급으로 나눠요 — 진짜 최소 요건 미만만 중단하고, 그 외 애매한 상태는 경고 후 계속 진행하며, 메시지에 감지된 값과 요구 범위를 함께 명시해요.

### Key Entities

- **셋업 단계 상태**: 단계별(CLI 설치 / 마켓플레이스 / 플러그인 / MCP) 완료·미완료·실패 — 멱등 재실행과 재개 판단의 근거예요.
- **설치 산출물(footprint)**: 사용자 머신에 만들어지는 항목 목록과 위치 — 설계 문서 §4.3 이 기준이에요.
- **핸드오프 카드**: 셋업 종료 시 사용자가 다음에 할 한 가지 행동을 알려주는 출력물이에요.

## Success Criteria *(mandatory)*

- **SC-001**: 신규 사용자가 셋업을 시작해 앱 작업 가능 상태(Ready)까지 필요한 사용자 액션이 8개에서 4개 이하(터미널 1 + Claude 안 대화형 3)로 줄어요.
- **SC-002**: 일반적인 네트워크 환경에서 명령 실행 시작부터 핸드오프 카드까지 5분 이내에 끝나요.
- **SC-003**: 같은 머신에서 명령을 두 번 연속 실행하면 두 번째 실행은 아무것도 바꾸지 않고 완료 상태만 보여줘요(멱등 100%).
- **SC-004**: 신규 사용자의 필수 Claude Code 재시작 횟수가 2회에서 1회로 줄어요.
- **SC-005**: 문서·안내 페이지의 빠른 시작 절차가 여러 단계에서 복사 가능한 명령 한 줄로 줄어요.
- **SC-006**: admin 권한 없는 계정에서도 셋업 성공률이 권한 있는 계정과 동일해요.
- **SC-007**: 프롬프트 응답이 불가능한 환경(CI·자동화 도구의 대행 실행)에서 입력 대기 상태로 남는 실행이 0건이에요.

## Assumptions

- 대상 머신에 Node.js 18+ 가 설치되어 있어요 — npx 방식 선택의 트레이드오프로, 브레인스토밍에서 결정했어요. Node 부재 환경은 안내 페이지 fallback 과 추후 별도 채널로 대응해요.
- npm 레지스트리(또는 사내 미러)에 접근할 수 있어요.
- `axhub` npm 패키지 이름은 팀이 이미 확보했어요(2026-04 선점 확인).
- 구버전 CLI 가 발견되면 최신으로 갱신하는 것이 기본 동작이에요.
- 명령 표면 `npx axhub@latest setup` 은 사용자가 결정한 제품 표면이에요 — 구현 세부가 아니라 UX 요구사항으로 취급해요.

## Out of Scope

- Claude Code 자체 설치 대행 — 감지와 안내만 해요.
- 터미널에서의 로그인 자동화 — 대화형 온보딩 담당을 유지해요.
- B2B 조직 일괄 배포(admin provisioning) — 후속 검토 항목이에요.
- `curl | sh` 등 Node 무관 설치 채널 — Node 부재가 실측으로 문제가 되면 재검토해요.

## Dependencies

- ax-hub-cli 저장소 — 셋업 오케스트레이션 명령 구현과 배포 파이프라인 소관이에요(이 plugin 저장소 밖 follow-up).
- Claude Code 의 플러그인·MCP 관리 명령 표면 — 비대화형 등록의 전제예요.
- 기존 `onboarding` 스킬 — 대화형 단계 인수인계 대상이에요.
- 승인된 설계 문서: `docs/superpowers/specs/2026-07-10-npx-one-command-onboarding-design.md`.
