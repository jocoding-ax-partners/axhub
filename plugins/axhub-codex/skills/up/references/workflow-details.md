# up — 분기 상세

SKILL.md 본문이 실행에 필요한 전부를 담아요. 이 문서는 참고용 배경이에요.

## 이 lane 의 두 진입

두 진입은 같은 명령을 쓰지만 사용자에게 다르게 설명해요.

- **저장소 없음 (평시).** `github_connected` 가 false 예요. 앱에 저장소가 없는 정상 상태이고, 받을 push 웹훅이 없어서 명시적 배포가 유일한 출고 경로예요. 실패가 아니니 push 를 시도하지 않고 복구로 알리지도 않아요.
- **GitHub 차단 (복구).** `github_connected` 가 true 인데 GitHub 자체 때문에 push 나 containment 가 막혔어요 — 권한 거부, 비공개 저장소 404, 조직 정책, device flow 만료. 이때만 복구 문구를 써요. 네트워크·타임아웃·5xx 는 일시 오류라 같은 단계를 한 번 재시도한 뒤에 판단해요. 여기서 그냥 넘어가면 사용자가 이미 갖고 있던 저장소와 push 자동 배포를 조용히 버리게 돼요.

두 진입 모두 앱이 이미 존재하고 `APP_ID` 가 잡혀 있어야 해요. 이 lane 은 앱이나 저장소를 만들지 않아요 — 그건 `bootstrap` 과 `import` 소관이에요.

## deploy 에서 넘어온 경우

`deploy` 가 작업 트리가 깨끗해서 preflight 까지 도달했고 거기서 `github_connected` false 나 GitHub 차단을 확인했으면, preview·승인 **전에** 이 스킬로 넘겨요. 그 시점에는 아직 아무것도 바뀌지 않아서 인계가 안전해요.

넘겨받을 때 `APP_ID` 와 사유(저장소 없음 / GitHub 차단)를 그대로 이어받아요. preview 카드·승인·실행·verify 는 이 스킬이 처음부터 해요 — `deploy` 의 첫 카드를 승인으로 승계하지 않아요.

작업 트리가 dirty 하면 `deploy` 는 첫 명령에서 이미 멈춰 여기까지 오지 못해요. 그 경로는 사용자가 이 스킬을 직접 부르는 것으로만 열려요.

## 패킹 규칙

CLI 가 하는 일이라 스킬이 흉내 내지 않아요. 사용자에게 설명할 때만 쓰는 사실이에요.

- 항상 제외: `.git/`, `node_modules/`, `.venv/`, `__pycache__/`
- `.env` 로 시작하는 파일은 제외하되 `.env.example`·`.env.sample`·`.env.template` 은 남겨요 — 없으면 빌드가 깨지는 앱이 있어서예요.
- 디렉터리별 `.gitignore` 를 존중해요. 아주 드문 패턴은 매칭되지 않아 파일이 **포함**되는 쪽으로 기울어요 — 과잉 제외가 빌드를 깨뜨리는 것보다 낫기 때문이에요.
- 업로드 상한과 단일 파일 상한이 있어요. 넘으면 CLI 가 올리기 전에 한국어 사유로 끊어요.

## source 버전

소스 버전은 내용으로만 정해져요 — 경로·내용·실행 권한만 반영하고 수정 시각과 소유자는 무시해요. 파일을 열어보기만 하거나 다시 묶기만 하면 같은 버전이라 재빌드가 일어나지 않고, 한 글자라도 고치면 새 버전으로 다시 빌드돼요.

같은 소스인데도 이미지를 새로 빌드해야 하면 `--force-rebuild` 를 붙여요. 사용자가 명시적으로 요청했을 때만 써요.

## 실패를 사용자에게 옮길 때

CLI 가 준 한국어 사유가 이미 사용자용 문장이에요. 그대로 전하고 exit 번호나 영어 원문을 덧붙이지 않아요. 사유가 영어로만 오면 한국어로 옮기되 없는 원인을 지어내지 않아요.
